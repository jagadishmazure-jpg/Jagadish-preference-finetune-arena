# Security policy

This is a portfolio project. Nothing in it is deployed, and it holds no real data: the company (Fenwold
Outdoor Supply) is fictional, and every prompt, policy and answer is generated by `prefarena/` and
open models running locally.

## Report a vulnerability

Please report privately through GitHub: open the **Security** tab and choose **Report a vulnerability**
(private vulnerability reporting is on). Please do not open a public issue. First reply within a week.

## Controls in place

- Secret scanning with push protection, Dependabot alerts and security updates
- CodeQL (`security-and-quality`) on every push and weekly
- gitleaks over the full git history in CI
- Every GitHub Action pinned to a commit SHA; workflow tokens are read-only
- `main` is protected: no force-push or deletion, and pull requests need the CI checks
- The deploy workflow is manual, gated by `DEPLOY_ENABLED`, and logs in with OIDC (no client secret)
- Model weights are downloaded from pinned URLs or a pinned revision and checked by SHA-256; weights
  load from safetensors or GGUF, never from pickle files
- Measured outputs (candidates, judge replies, embeddings, tuned answers) are checked against a hash
  manifest, so a changed data file fails CI
- A safety regression set is gated in CI: tuned models may not refuse fewer unsafe requests than the base
